01 — The Big Idea

What is Sentio?

Sentio is a real-time stock sentiment pipeline. Every 30 seconds it reads financial news headlines, figures out whether the news is positive or negative, stores that score per stock, and streams it live to a browser dashboard.

Imagine you hired someone to read every financial news article about TSLA, AAPL, and NVDA all day. After each article they text you: "TSLA — positive (0.72)" or "AAPL — negative (-0.45)". Sentio does exactly that, but fully automated, in real time, for free.

The score comes from VADER — a sentiment model that runs entirely on your machine. No API key, no cost. It reads a headline like "Tesla recalls 200,000 vehicles" and outputs -0.68. A headline like "NVIDIA smashes earnings expectations" gets +0.91.

📈 What it shows

A live dashboard with a sentiment score per ticker, a rolling chart, and the last 20 headlines that drove the score.

🏆 Why it's impressive

It's reactive end-to-end — WebFlux + Kafka + SSE. No other open-source tool in this space is built this way.

💰 Cost to run

Zero. Free RSS feeds, free Yahoo Finance API, VADER runs locally, Docker for Kafka + Redis.

🎯 Resume value

Covers reactive programming, message brokers, NLP, Redis, SSE streaming — 5 advanced topics in one project.

02 — The Pipeline

How data flows through Sentio

Sentio has 6 layers. Each one does one job and passes data to the next. Think of it like an assembly line.

📰

Layer 1 — RSS Scraper RssScraper.java

Every 30 seconds, fetches Yahoo Finance RSS feeds for AAPL, TSLA, NVDA, MSFT. Uses a library called Rome to parse the XML. Each article becomes a NewsArticle object with a title, description, and timestamp. Publishes it to Kafka.

📬

Layer 2 — Kafka KafkaTopicConfig.java

Think of Kafka as a post office with 3 mailboxes: raw-news, price-tick, and sentiment-out. The scraper drops articles in raw-news. The processor picks them up. If the processor is slow, articles queue up safely — nothing gets lost.

🧠

Layer 3 — VADER Processor SentimentProcessorService.java

Reads articles from Kafka. For each one, runs VADER sentiment analysis on the headline. VADER returns a compound score between -1.0 and +1.0. Above 0.05 = positive, below -0.05 = negative, in between = neutral. Takes ~2ms per headline. Results go to Redis and Kafka sentiment-out.

🗄️

Layer 4 — Redis Storage SentimentAggregator.java

Redis is a super-fast in-memory database. We store two things per ticker: a list of the last 50 scored headlines, and a sorted set of scores over the last 24 hours. When the dashboard asks "what's TSLA's mood right now?", Redis answers in under 1ms.

📡

Layer 5 — SSE Endpoint SentimentStreamController.java

SSE = Server-Sent Events. The browser connects once to /api/sentiment/stream/AAPL and the server pushes new scores automatically whenever they arrive. No polling. Also sends a heartbeat every 15s so the connection stays alive through proxies.

🖥️

Layer 6 — Dashboard index.html

Vanilla JS + Chart.js. Uses the browser's built-in EventSource API to connect to the SSE endpoint. Updates a live chart and headline feed every time a new sentiment event arrives. No React, no framework needed.

03 — Tech Stack

Every technology, explained simply

Here's what each tool is, what it does in Sentio, and why we picked it over alternatives.

🌿

Spring WebFlux

The reactive backbone of the whole backend. Unlike regular Spring MVC which blocks a thread per request, WebFlux handles thousands of connections with very few threads. Essential for SSE streaming.

📮

Apache Kafka

A message broker — sits between the scraper and the processor so they're completely independent. If the processor crashes, Kafka holds the messages until it restarts. Industry standard at every major fintech.

⚡

Redis

In-memory key-value store. We use it to cache the last 50 headlines per ticker and the rolling 24h score history. Reads take under 1ms, making the dashboard feel instant.

🧠

VADER Sentiment

A rule-based NLP model specifically built for short social/news text. Runs fully locally in the JVM — no server calls, no API key, no cost. Scores a headline in ~2ms.

🔗

Rome RSS Parser

Java library that parses RSS/Atom feeds. Yahoo Finance exposes free RSS feeds per ticker — no API key needed. Rome turns the XML into Java objects we can work with.

📡

SSE (Server-Sent Events)

A browser protocol for one-way server→client streaming. Simpler than WebSockets for this use case. The browser's built-in EventSource API handles reconnection automatically.

🐳

Docker Compose

Runs Kafka and Redis locally with one command: docker-compose up -d. No manual installation. Same config works on Railway for deployment.

📊

Chart.js

Frontend charting library. We use it to draw the live sentiment score timeline. Loaded via CDN — no npm, no build step needed for the dashboard.

What we designed vs what's left

  • Add manual deps: Rome, Reactor-Kafka, VADER to pom.xml
  • Set up application.yml with Kafka, Redis, ticker list config
  • Create package structure: config, model, scraper, processor, stream, controller
  • Start Docker Compose to run Kafka + Redis locally
PHASE 02 ⬜ Model classes (DTOs) BUILD FIRST ›
  • Create NewsArticle.java — title, description, publishedAt, sourceUrl
  • Create SentimentResult.java — ticker, headline, compound score, label, timestamp
  • Create PriceTick.java — ticker, price, change, changePercent, volume, fetchedAt
  • Create SentimentSnapshot.java — for the /summary endpoint response
  • Create SentimentLabel.java enum — POSITIVE, NEGATIVE, NEUTRAL
PHASE 03 ⬜ Kafka config + producer service BUILD SECOND ›
  • Create KafkaTopicConfig.java — define raw-news, price-tick, sentiment-out topics
  • Create KafkaProducerService.java — wraps ReactiveKafkaProducerTemplate, serializes to JSON
  • Create KafkaConsumerConfig.java — consumer group, deserializers
  • Test: verify topics are created in Kafka when the app starts
PHASE 04 ⬜ RSS Scraper + Price Poller BUILD THIRD ›
  • Create RssScraper.java — Flux.interval, Rome feed parse, publish to raw-news
  • Create YahooPricePoller.java — WebClient to query1.finance.yahoo.com, publish to price-tick
  • Create PriceStore.java — save/get latest PriceTick in Redis with 5min TTL
  • Test: check Kafka raw-news topic receives messages using Kafka console consumer
PHASE 05 ⬜ VADER Sentiment Processor BUILD FOURTH ›
  • Create SentimentProcessorService.java — Kafka consumer, runs VADER, emits SentimentResult
  • Create SentimentAggregator.java — saves to Redis list + sorted set, pruning logic
  • Implement buildSnapshot() — computes rolling average, trend, recent headlines
  • Test: log compound scores to console, verify they make sense for the headlines
PHASE 06 ⬜ SSE Streaming Endpoint BUILD FIFTH ›
  • Create SentimentStreamService.java — shared multicasted Flux per ticker, dedup logic
  • Create SentimentStreamController.java — /stream/{ticker}, /snapshot, /summary endpoints
  • Create PriceController.java — /api/price/{ticker} and /full combined endpoint
  • Create CorsConfig.java — allow localhost:3000 for EventSource
  • Test: open browser, hit /stream/AAPL, watch events appear
PHASE 07 ⬜ Frontend Dashboard BUILD SIXTH ›
  • Build index.html — ticker buttons, score display, Chart.js timeline, headline feed
  • Connect EventSource to /stream/{ticker} — live updates on sentiment events
  • Load snapshot on ticker switch for instant initial data
  • Style with green/red color coding per sentiment label
PHASE 08 ⬜ Deploy to Railway LATER ›
  • Write Dockerfile — same pattern as Riffly
  • Write railway.toml — start command, health check
  • Set up Railway environment variables for Kafka and Redis URLs
  • Write README.md with architecture diagram for GitHub
